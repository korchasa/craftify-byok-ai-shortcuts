### Этап 3: Реализация общей библиотеки CraftifyShared

**Вопросы к stakeholder:**
1. Нужно ли поддерживать fallback для AuthManager при недоступном Keychain?
2. Какие форматы логов обязательны (SQLite vs. CoreData)?
3. Обязательна ли поддержка in‑memory stub для всех менеджеров?
4. Нужны ли расширенные метаданные в логах (device, OS‑версия)?
5. Какие требования к оборачиванию ошибок?
6. Есть ли требования к скорости операций AuthManager/LogManager?

**Последовательность действий для самостоятельной реализации:**
1. Инициализируй новый SPM‑пакет `CraftifyShared`.
2. Создай модуль `Models` с энумами операций и параметров.
3. Реализуй протокол `AuthManaging`.
4. Напиши класс `AuthManager` с Keychain Sharing.
5. Создай stub на основе UserDefaults для unit‑тестов.
6. Напиши unit‑тесты для AuthManager: чтение/запись, ошибки.
7. Реализуй `LogManagerShared`: выбор SQLite или CoreData.
8. Добавь FIFO‑механизм: удаление старых записей при > 1000.
9. Напиши unit‑тесты для LogManager: создание, чтение, удаление.
10. Добавь маскирование ключа в логах (first/last 4 chars).
11. Проверь производительность: замер записи 1000 логов.
12. Задокументируй API AuthManager и LogManager в Markdown.
13. Создай пример использования в `ExampleApp`.
14. Настрой CI‑job на проверку покрытия (`coverage ≥ 100%` для AuthManager).
15. Убедись, что SPM‑пакет собирается без зависимостей на UIKit.

**Definition Of Done:**
- SPM пакет компилируется без ошибок отдельно.
- Unit‑тесты покрывают AuthManager и LogManager на 100%.
- Документация API актуальна.
