# Whiteboard: E2E тесты Craftify

## Запрос пользователя
Реализовать end-to-end тесты для всего реализованного функционала.

## Анализ задачи
- Требуется покрыть e2e тестами все ключевые пользовательские сценарии, включая edge-cases и негативные сценарии, для MainApp и Share Extension.
- Тесты должны быть интегрированы в CI/CD, запускаться через `./run test:unit` и обеспечивать покрытие ≥ 80%.
- В документации и roadmap явно указано: e2e тесты обязательны для всех пользовательских сценариев (onboarding, inventory, settings, share flow, ошибки, буфер обмена, согласие, длинный текст, неверный ключ, отмена, edge-cases).
- В проекте уже есть UI и unit тесты для MainApp, e2e тесты для всех пользовательских сценариев (onboarding, inventory, settings, share flow, ошибки, буфер обмена, согласие, длинный текст, неверный ключ, отмена, edge-cases) реализованы и проходят.

## Декомпозиция задачи
1. **Onboarding flow**
   - [x] Первый запуск, согласие, переход в HomeView.
   - [x] Edge-case: отказ от согласия — кнопка неактивна.
2. **Inventory management**
   - [x] Добавление, редактирование, удаление операций.
   - [x] Edge-case: попытка добавить некорректную операцию.

   - [x] Edge-cases:
     - [x] Нет текста — Alert.
     - [x] Слишком длинный текст — Alert.

## Потенциальные сложности и решения
- **Тестирование Share Extension**: требуется симуляция share flow через simctl/XCUITest, возможно использование вспомогательных приложений/хелперов.
- **Stub OpenAI API**: интеграция OHHTTPStubs для эмуляции ответов (успех, ошибки, задержки).
- **Буфер обмена**: использовать тестовые double для ClipboardManager.
- **App Group/Keychain**: для тестов использовать in-memory stub.
- **Параллельный запуск**: обеспечить изоляцию данных между тестами.

## Анализ проблемы с тестом testLogWriteMaskExportFIFO (логирование и маскирование API-ключа)

### Суть проблемы
- Тест ожидает маску API-ключа вида "sk-12****cdef" (5 символов prefix), но функция maskAPIKey возвращает "sk-1****cdef" (4 символа prefix).
- В коде LogManagerShared используется maskLength = 4 (prefix и suffix по 4 символа).
- В AuthManager используется другая логика (prefix 3, suffix 4, min длина 8).
- В тесте зашито ожидание, не совпадающее с реализацией.

### Варианты решения
1. Унифицировать маскирование API-ключа во всех менеджерах (рекомендуется для консистентности):
   - Вынести maskAPIKey в общий протокол/расширение.
   - Использовать одинаковую логику (например, 4+4 символа, min длина 8).
2. Исправить тест testLogWriteMaskExportFIFO, чтобы он ожидал "sk-1****cdef".

### План действий
1. Зафиксировать анализ и план.
2. Унифицировать maskAPIKey во всех менеджерах (CraftifyShared), покрыть unit-тестами граничные случаи.
3. Исправить тест testLogWriteMaskExportFIFO под новую логику.
4. Запустить тесты, убедиться в прохождении.
5. Обновить документацию (implementation.md, developer-manual.md, code-style-swift.md).
6. Удалить whiteboard.md после завершения.
