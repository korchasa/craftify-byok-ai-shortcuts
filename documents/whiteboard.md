# [2024-06-09] Исправление обработки URL для операций

## Проблема
- В summarize url отправлялся напрямую в LLM, а не преобразовывался в текст.
- Не было единого способа для операций обрабатывать url/text.

## Решение
- В протокол OperationType добавлен асинхронный метод resolveInput.
- Для SummarizeOperation: поддержка url (загрузка и парсинг текста).
- Для остальных операций: только text, url вызывает ошибку.
- ViewModel всегда вызывает resolveInput перед отправкой текста в LLM.
- Теперь url не отправляется напрямую в LLM.

# Текущие задачи и прогресс

## [Выполнено] Заголовок окна результата = название операции без параметров
- Требование: заголовок окна с текстом результата должен быть равен названию операции (Summarize, Explain и т.д.), без параметров.
- Анализ: ранее заголовок мог содержать параметры (язык, детализацию и т.д.).
- Решение: добавлена функция operationTitle(for:), возвращающая только название операции по типу (с локализацией). Заголовок теперь формируется только по типу операции.
- В ShareExtensionManager добавлено хранение типа последней выполненной операции (lastOperationKind).
- Все проверки и тесты пройдены, ошибок не обнаружено.
