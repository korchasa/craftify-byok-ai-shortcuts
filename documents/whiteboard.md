# Task: Always Use Current User Language from Settings in Operations

## Goal
Обеспечить, чтобы "родной язык" пользователя (nativeLanguage) не сохранялся в параметрах операций (например, simplify, summarize, explain), а всегда получался из актуальных настроек пользователя при каждом вызове операции. Это устранит проблему, когда после смены языка в настройках старые операции продолжают использовать устаревшее значение.

## Overview
- Сейчас nativeLanguage сохраняется в OperationInput и сериализуется в параметры операций (Explain, Summarize и др.).
- При смене языка в настройках, старые операции продолжают использовать старое значение, т.к. оно сохранено в параметрах.
- Требуется изменить архитектуру: nativeLanguage должен быть удалён из OperationInput и сериализуемых параметров операций.
- Все операции, которым нужен родной язык, должны получать его только через сервис (например, AppSettingsManager), который возвращает актуальное значение из UserDefaults/App Group.
- Для всех настроек приложения (не только языка) должен быть отдельный сервис (AppSettingsManager), который централизованно управляет доступом к настройкам.
- ViewModel'и не должны сохранять язык в OperationInput.
- Это затрагивает MainApp и ShareExtension, а также все операции, использующие родной язык (explain, summarize и др.), все ViewModel'и, сериализацию/десериализацию OperationInput, тесты.

## Definition of Done
- Операции (explain, summarize и др.) всегда используют актуальное значение родного языка из настроек пользователя через сервис.
- После смены языка в настройках все операции используют новое значение без необходимости пересоздавать их.
- Поле nativeLanguage удалено из OperationInput и сериализуемых параметров операций.
- Для всех настроек приложения реализован отдельный сервис (AppSettingsManager), который используется во всех слоях приложения.
- Все тесты (unit) проходят успешно.
- Нет регрессий, warnings, ошибок форматирования и линтинга.
- Документация обновлена.
